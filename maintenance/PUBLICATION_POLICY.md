# Publication boundaries

## Source and rights

The owner permits a public repository while retaining the existing **All Rights Reserved** position. Public is a visibility choice, not an open-source license. `LICENSE` is preserved; no MIT, Apache, or Creative Commons grant is introduced. GitHub's own terms govern its public viewing/forking features. Third-party software and data keep their own licenses and notices.

Inventory dependency licenses and advisory-data provenance before claiming that all repository content is exclusively owned by the project. `requirements.txt` entries are dependencies, not permissions to relicense them. No legal clearance of third-party material is asserted by this audit.

## Content classes

| Class | Handling |
| --- | --- |
| Project source, templates, generic diagrams | Public-source candidates under the project rights notice |
| Synthetic benchmark cases | Retain as labeled fixtures; apparent credentials are not to be verified live |
| Existing candidate lists and cross-tool site-level files | Already tracked; retain unchanged for evidence continuity, flag for a separate release review |
| Raw scan JSON, archive, manifests, personal research notes | Local by default; never bulk-add |
| Paper/reanalysis files in `output/` | Local until a selected, sanitized release is prepared |
| Local secrets, Azure settings, Terraform state/plans | Never publish; ignore rules do not remove prior Git history |
| Historical URLs, subscription identifiers, deployment notes | Operational metadata, not automatically credentials; minimize in later public documentation |

The tracked candidate lists and calibration records identify third-party sites. This cleanup does not anonymize them, remove them from history, or certify them for a new research-data release. A hash of a domain or scan identifier is not a guarantee of anonymity. Preserve originals and make reviewed derivatives separately.

## Research disclosure

The author states that the historical study had no site-owner permissions, no institutional ethical approval, no disclosure notifications, and no manual review. Future documentation must state these facts without replacing them with claims of unavailable records. This statement does not establish the historical live-key-verification setting. Public accessibility and read-oriented traffic do not imply authorization or harmlessness.

## Release boundary

No push, public visibility change, Pages publication, credential validation, cloud deployment, or history rewrite is performed by the cleanup. The existing public site, if any, is not updated until publication is explicitly dispatched. The remaining content reconciliation and release review are recorded in the audit.
